## 任务

对当前分支相对于目标分支的所有代码变更进行全面的 Code Review，输出结构化的审查报告。

## 输入参数

- 目标分支（可选）：`$ARGUMENTS`
- 如果未传入，默认与 `master` 分支进行对比

## 执行步骤

### 1. 获取变更概览

- 执行 `git diff $TARGET_BRANCH...HEAD --stat` 查看变更文件列表和统计
- 执行 `git log $TARGET_BRANCH...HEAD --oneline` 查看本分支所有 commit 记录
- 确认当前分支名称：`git branch --show-current`

### 2. 逐文件分析变更

- 执行 `git diff $TARGET_BRANCH...HEAD -- <file>` 查看每个变更文件的具体 diff
- 对于新增文件，查看完整内容
- 对于删除文件，记录删除原因

### 3. 审查维度

请从以下维度进行审查，并对每个维度给出评分（✅ 通过 / ⚠️ 需关注 / ❌ 有问题）：

#### 3.1 代码正确性

- 逻辑是否正确，边界条件是否处理
- 是否存在潜在的运行时错误（空引用、类型错误等）
- 异步操作是否正确处理（await/错误捕获）

#### 3.2 代码规范

- 是否符合项目的 Vue 3 + TypeScript + Composition API 规范
- 组件是否使用 `<script setup lang="ts">`
- 样式是否使用 `<style lang="scss" scoped>` + BEM 命名
- 注释是否为中文
- 变量/函数命名是否清晰合理

#### 3.3 性能与优化

- 是否有不必要的重复渲染或计算
- 响应式数据使用是否合理（ref vs reactive vs computed）
- 是否有内存泄漏风险（事件监听未清理、定时器未清除等）

#### 3.4 可维护性

- 代码是否易于理解和维护
- 是否有重复代码可以抽取
- 组件/函数职责是否单一
- 是否有硬编码的魔法数字或字符串

#### 3.5 安全性

- 是否有 XSS 风险（v-html 使用等）
- 敏感信息是否暴露
- API 调用是否安全

### 4. 输出审查报告

按以下格式输出：

```
🔍 Code Review 报告

📋 基本信息
- 当前分支：<branch name>
- 对比分支：<target branch>
- 变更文件数：<count>
- 提交次数：<commit count>

📊 总体评分：<A/B/C/D>（A=优秀 B=良好 C=需改进 D=需重构）

---

✅ 做得好的地方
- ...

---

⚠️ 需要关注的问题

【严重程度：高/中/低】
📄 文件：<filename>
📍 位置：<line range>
💬 问题：<description>
💡 建议：<suggestion>

---

📝 改进建议
- ...

---

📊 各维度评分
- 代码正确性：✅ / ⚠️ / ❌
- 代码规范：✅ / ⚠️ / ❌
- 性能与优化：✅ / ⚠️ / ❌
- 可维护性：✅ / ⚠️ / ❌
- 安全性：✅ / ⚠️ / ❌
```

### 5. 注意事项

- 重点关注业务逻辑的正确性，而非代码风格的细枝末节
- 对于有隐患的代码，给出具体的修复建议和示例代码
- 如果变更文件过多（超过 20 个），先给出总体概览，再按优先级逐个分析
- 对确实写得好的代码也要给予肯定
